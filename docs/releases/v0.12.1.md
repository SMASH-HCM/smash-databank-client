SMASH-HCM Databank Client 0.12.1

- Fix manifest validation for the published `schema_version: "1.0"` inventory. Legacy numeric versions remain supported; newer versions are accepted when the required layout and integrity fields are compatible.
- Support the databank's `entries` catalogue as well as the earlier `release`/`files` layout. Explicit database references enable the database download choice; directory digests remain metadata rather than file checksums. Cohort membership is never inferred from paths.
- Save a validated `manifest.json` into the confirmed download folder, while retaining the authoritative private cache for ETags/receipts. Invalid downloads preserve both previous copies. A locked visible copy gives a warning without discarding a usable cache.
- Display `validating` after transfer, and report specific manifest-validation failures at startup.
- Verified against the live Nextcloud manifest on 21 October 2026: schema 1.0, 472 files, 29 directory records. No clinical files were downloaded in that check. Separately, the advertised `SMASH_v1.4_rc5.db` returned HTTP 404 for the configured account; this is an upstream file availability/path/permissions issue, not a manifest-schema validation failure.

Manifest updates and changes to clinical files remain separate: updated data files still require selection/confirmation and pass byte-size/SHA-256 checks. The Nextcloud update flow does not replace the application executable.
