SMASH-HCM Databank client 0.11.0

- Startup checks server reachability, local database availability, and configured authenticated databank access. Successful login offers a Y/N data-update check.
- Validated manifest caching supports ETags; files are compared by SHA-256/size, with optional stable artifact IDs across versioned paths.
- Selected updates support archive, keep, or explicitly confirmed replacement. The new file is verified before any old-file deletion; database replacements must also contain a readable OMOP person table. Durable old-version history survives interrupted installs.
- New Python installations share the home-based application profile; existing checkout profiles and `.env` files remain compatible.
- Python wheel/source distributions accompany folder-mode Windows builds. Native Linux and Apple Silicon/Intel Mac jobs are available through the release workflow; review their actual results before distributing those builds.

Data stays on the authenticated SMASH Nextcloud service. No database, clinical files or credentials are included in application downloads. This checks data versions, not automatic executable updates.

The baseline availability mask, exact-day defaults and explicit history options remain documented in DATASET_EXPORTS.md. Missing source anchors still block affected baseline exports; these changes do not repair or rewrite the source OMOP database. Multiple training indices/outcome risk sets are not inferred.

Extract the whole platform ZIP, or install the Python wheel with the UI/secure extras. Checksums accompany release assets. Mac binaries are unsigned/not notarized. Review UPDATES.md and GITHUB_RELEASE.md for the update and installation workflow.
